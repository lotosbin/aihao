# 字体与中文显示

> 本文说明为什么内置中文字体、内置了哪一份、如何重新生成，以及它的已知边界。
> 代码落点：`app/shared/src/ui/ChenmiShaTheme.kt`、`app/shared/composeResources/font/`。

## 1. 问题

Compose Multiplatform 的文字最终由 Skia 绘制。在 **Web(Wasm)** 端，文字画进 canvas，
Compose 不会自动接入浏览器的系统字体回退链；**Android/iOS/Desktop** 也只在系统恰好提供
对应中文字体时才正常。结果是：不显式提供 CJK 字体时，中文会渲染成空白或豆腐块（tofu）。

所以「中文字体」在本项目里不是装饰，而是**显示正确性的前置条件**，必须随应用内置。

## 2. 方案

内置 **霞鹜文楷（LXGW WenKai）**，并把它设为全站默认字体族。

- 上游：<https://github.com/lxgw/LxgwWenKai>
- 版本：`v1.522`
- 文件：`app/shared/composeResources/font/lxgw_wenkai_regular.ttf`
- 许可：SIL Open Font License 1.1，见 `licenses/LXGWWenKai-OFL.txt`

应用方式：`ChenmiShaTheme` 把该字体族写进 Material 3 的**全部 15 个文字样式**
（`Typography` 没有「统一换字体族」的入口，只能逐项 `copy`），因此不存在漏掉某个样式
而局部回退到无中文字形默认字体的可能。

```kotlin
ChenmiShaTheme {          // app/shared/src/App.kt
    ChenmiShaApp(...)
}
```

## 3. 为什么是子集，而不是发行版全量字体

霞鹜文楷发行版全量 TTF 约 **24 MB**（46867 个字形，覆盖 GB18030 与扩展区）。
对 Web(Wasm) 与移动端来说过重：本项目 wasm 产物本身已有约 22.7 MB，
再叠一份 24 MB 字体，首屏体积会翻倍。

因此内置的是**子集化**版本：

| | 全量发行版 | 本项目子集 |
| :--- | :--- | :--- |
| 文件体积 | 25,575,676 B（24.39 MB） | 3,727,616 B（**3.55 MB**） |
| 字形数 | 46,867 | 8,232 |
| cmap 码位 | 46,490 | 7,835 |

字符集构成（共 7909 个字符）：

1. **GB2312 全集**（6763 汉字 + 符号）—— 覆盖正常简体中文写作；
2. **仓库实际用字**（扫描 `core/src/content/**`、`app/shared/src/**` 及文档）；
3. **拉丁字、常用标点、CJK 标点、全角字符**（`U+0020-007E`、`U+00A0-00FF`、
   `U+2000-206F`、`U+3000-303F`、`U+FF00-FFEF`）。

**许可依据**：OFL 1.1 的 ADDITIONAL PERMISSION 明确允许「subsetted or converted to other
formats (e.g., WOFF/WOFF2) solely for web font delivery」，前提是不得作为可安装的桌面字体分发。
本项目只作为应用内置字体使用，符合该条款；OFL 要求保留的版权声明与许可全文已随仓库保存。

## 4. 覆盖率校验

每次生成子集时都会校验：内容库与 UI 源码中出现的每个 `> U+2000` 的字符都必须命中子集 cmap。
当前结果：

```
✓ 15 个源文件的中文字符全部被子集覆盖
```

该校验是硬失败（缺字即非零退出），避免「改了文案却显示成豆腐块」这种线上才暴露的问题。

## 5. 如何重新生成

内容新增了 GB2312 之外的生僻字时，或需要升级字体版本时：

```bash
python3 -m venv /tmp/ftenv
/tmp/ftenv/bin/pip install fonttools brotli
bash tools/subset-lxgw-font.sh
```

脚本会：下载指定版本的发行版字体 → 重新扫描仓库生成字符集 → 子集化到
`app/shared/composeResources/font/lxgw_wenkai_regular.ttf` → 校验覆盖率。
版本号与输出路径都在脚本头部，升级字体只需改 `LXGW_VERSION`。

## 6. 已知边界

1. **生僻字**：不在子集内（GB18030 扩展区）会显示为豆腐块。若确实需要，重新运行上面的脚本
   （新内容会被重新扫描进来），或改造脚本改用发行版全量字体。用户共创提交的爱好若含生僻字，
   上线前需重新生成子集。
2. **首帧**：字体作为资源异步加载，理论上存在极短暂的回退窗口。当前未做加载门控，
   如需绝对无回退，可在 `ChenmiShaTheme` 里用 `preloadFont` 阻塞首帧。
3. **Web 端体积**：wasm 约 22.7 MB + 字体 3.55 MB。若还要压，优先方向是按页面实际用字再收窄子集；
   注意 **Skia 不支持 woff2**，不要指望用 woff2 压缩字体文件。
4. **字重**：当前只内置 Regular（400）。Material 3 中 `labelLarge` 等样式请求 W500 时，
   由 Skia 合成加粗。若设计要求真实 Medium/Bold，需要再引入 `LXGWWenKai-Medium.ttf`
   等字重并构造成多字重的 `FontFamily`。

## 7. 平台说明

内置字体对四个平台同时生效，因此 Android / iOS / Desktop / Web 的观感一致，
不依赖各平台系统是否安装中文字体。代价是各端产物都增大 3.55 MB —— 这是当前一致性优先的选择，
若后续希望 Android/iOS 放弃内置、改用系统中文字体以减小包体，需要按平台拆分字体配置。
